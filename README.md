# SlopCord

Легкий голосовий чат для друзів під Windows (Tauri 2 + React + TypeScript, голос через LiveKit Cloud).

Зараз це **етап 0**: прототип, у якому двоє (або до 10) людей заходять у кімнату й чують одне одного.
Вхід, сервери друзів і текстовий чат будуть на етапі 1 разом із Supabase.

## Що вміє прототип

- Зайти в кімнату за назвою й говорити.
- Голосова активація за замовчуванням: мікрофон передає звук лише тоді, коли ти говориш. Чутливість регулюється повзунком.
- Вимкнути мікрофон, вимкнути звук (тоді сервер узагалі перестає надсилати тобі звук).
- Список учасників і зелене коло навколо того, хто говорить.
- Вибір мікрофона й навушників.
- Автоматичне перепідключення, якщо інтернет на секунду зник.
- Інтерфейс українською та англійською.

## Як запустити (без програмування)

### 1. Ключ LiveKit (один раз)

1. Зайди в [LiveKit Cloud](https://cloud.livekit.io), відкрий свій проєкт → **Settings**.
2. Увімкни **Development token server**.
3. Скопіюй **Token server ID**, що з'явиться під перемикачем.

Щоб друзям не треба було вводити ID, вший його в інсталятор:

1. У репозиторії на GitHub відкрий **Settings → Secrets and variables → Actions**.
2. Натисни **New repository secret**, назва `LIVEKIT_TOKEN_SERVER_ID`, значення — твій Token server ID.
3. Наступна збірка вже міститиме ID, і поле для нього в застосунку зникне.

Без секрету застосунок, як і раніше, попросить ввести ID вручну.
API Secret з LiveKit нікуди копіювати не треба.

> Development token server — тимчасове рішення для тестів: будь-хто з цим ID може зайти в кімнату.
> Тому не публікуй ID відкрито. На етапі 1 токени видаватиме Supabase і лише тим, хто увійшов.

### 2. Інсталятор

Друзям давай посилання на останній реліз: <https://github.com/IvanZhuravel/SlopCord/releases/latest>.
Там лежить `SlopCord_..._x64-setup.exe`. Windows може показати синє вікно SmartScreen: **Докладніше → Виконати все одно** (підпис коду платний, поки відкладаємо).

Ставити інсталятор треба лише один раз. Далі застосунок при запуску сам перевіряє нову версію й показує кнопку **Оновити**.
Під час розмови він нічого не перезапускає: оновитися можна після виходу з кімнати.

Тестові збірки з pull request-ів лежать у вкладці **Actions** → запуск **Build Windows app** → **Artifacts**.

### 3. Перевірка вдвох

1. Обидва вводите своє імʼя й однакову назву кімнати (і Token server ID, якщо він не вшитий).
2. Натискаєте **Зайти в кімнату** і дозволяєте доступ до мікрофона.
3. Говорите. Якщо тебе обрізає, тягни повзунок чутливості вліво; якщо друг чує клавіатуру чи вентилятор, тягни вправо.

## Оновлення й релізи

Новий реліз зʼявляється, коли в репозиторій пушать тег версії, наприклад `v0.2.0`, або коли у вкладці **Actions → Release → Run workflow** вводять номер версії (`0.2.0`).
Workflow **Release** збирає інсталятор, підписує його й публікує разом із `latest.json`, який читають уже встановлені застосунки.

Для цього потрібні два секрети в **Settings → Secrets and variables → Actions**:

- `TAURI_SIGNING_PRIVATE_KEY` — приватний ключ підпису оновлень;
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — пароль до нього.

Якщо ключ загубити, нові версії вже не підпишеш тим самим ключем, і друзям доведеться один раз перевстановити застосунок вручну.
Автооновлення працює, лише коли репозиторій публічний: з приватного застосунок не може скачати `latest.json`.

## База даних (Supabase)

Таблиці, правила доступу й сховища картинок описані в `supabase/migrations/`. Workflow **Supabase** перевіряє кожну міграцію на чистому Postgres, а після злиття в `main` сам розгортає їх у проєкт Supabase.

Для розгортання потрібні секрети `SUPABASE_ACCESS_TOKEN`, `SUPABASE_PROJECT_REF` і `SUPABASE_DB_PASSWORD`. Поки їх немає, розгортання пропускається з попередженням.

Один раз вручну: у Supabase відкрий **Authentication → Sign In / Providers → Email** і вимкни **Confirm email**.

Щоб застосунок знав, до якого проєкту Supabase підключатися, додай у **Settings → Secrets and variables → Actions → Variables** дві змінні (вони не секретні):

- `SUPABASE_URL` — Project URL з **Project Settings → API**;
- `SUPABASE_ANON_KEY` — ключ `anon public` звідти ж.

Поки їх немає, застосунок працює як прототип етапу 0: без входу, з полем для імені. На сервер однаково потрапляєш лише за кодом запрошення.

## Для розробки

Потрібні Node.js 22+, Rust і [залежності Tauri для Windows](https://v2.tauri.app/start/prerequisites/).

```bash
npm install
npm run tauri dev     # запуск із гарячим перезавантаженням
npm run tauri build   # інсталятор у src-tauri/target/release/bundle/nsis
```

## Як влаштовано

| Файл | Що робить |
| --- | --- |
| `src/voice.ts` | Підключення до LiveKit, учасники, мікрофон, звук, перепідключення |
| `src/voiceGate.ts`, `public/voice-gate.worklet.js` | Голосова активація. Працює в аудіопотоці, тож не залежить від того, згорнуте вікно чи ні |
| `src/App.tsx` | Увесь інтерфейс |
| `src/updater.ts` | Перевірка й встановлення оновлень |
| `src/supabase.ts`, `src/Auth.tsx` | Підключення до Supabase, вхід, реєстрація, профіль і аватар |
| `src/i18n.ts` | Тексти українською та англійською |
| `src-tauri/` | Оболонка Tauri (Rust) |
| `supabase/migrations/` | Таблиці, правила доступу (RLS), сховища файлів |

Оптимізація: Opus моно з DTX (коли мовчиш, майже нічого не надсилається), шумозаглушення й ехоподавлення вбудовані в WebView2, жодних таймерів у фоні, релізна збірка Rust із LTO, без важких UI-бібліотек.
